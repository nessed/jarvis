# L3 — bus/tunnel restart and read-only Meta reconnaissance

## Ownership

You may edit only `docs/tasks/browser-log.md`. Do not commit. Do not edit
`docs/context.md`; report the replacement tunnel URL and findings to the
orchestrator, who owns the handoff update. Never reveal credentials or tokens.

## Objective

1. Restart the local FastAPI bus and create a fresh Cloudflare Quick Tunnel.
   Verify the externally reachable protected health route. Record only the new
   public tunnel URL and safe reachability result in `docs/tasks/browser-log.md`.
2. In the browser, perform read-only reconnaissance at
   `developers.facebook.com` → My Apps. Identify the app with WhatsApp attached.
3. For that app, inspect and report the test number, Phone Number ID, App ID,
   recipient allow-list state for the user’s number, and existing WhatsApp
   Configuration callback URL / verify-token field state. Do not expose any
   secret values.

## Boundaries

- Touch nothing in the dashboard: no edits, no Save/Confirm, no token creation.
- Do not request re-verification if the recipient is already allowed.
- If authentication is needed, stop at the login wall and report the one batched
  user handoff needed. The user must perform login, 2FA, captcha, and all final
  Save/Confirm actions.
- Quick Tunnel URLs expire whenever their process stops; the result must be
  treated as temporary.
