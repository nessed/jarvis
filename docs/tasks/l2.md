# L2 — live provider-router verification

## Ownership

You may edit only `router/` and `tests/router/`. Do not commit. Do not edit
`docs/context.md`; report the exact outcome to the orchestrator, who owns the
handoff update. Do not reveal credential values.

## Objective

Verify the router against current provider behavior.

1. Confirm `router/providers.yaml` uses `deepseek-v4-flash`, not the retired
   `deepseek-chat` or `deepseek-reasoner` names.
2. Smoke-test the configured direct DeepSeek rung with one minimal request.
3. Prove the DeepSeek off-peak gate defers non-urgent work during the documented
   peak UTC windows (01:00–04:00 and 06:00–10:00) rather than only logging a
   warning. Add/adjust unit tests under `tests/router/` if necessary.
4. Smoke-test the configured Groq, Cerebras, and Gemini credentials with one
   minimal request each; confirm a 200-class response without exposing secrets.
5. Confirm cooldown parsing receives and records real response headers, not
   only mocked ones. Do not hardcode limits or model IDs.

Use current official provider documentation for any model-name or endpoint
claim before changing configuration. Report per-rung pass/fail and the exact
safe failure reason where applicable.
